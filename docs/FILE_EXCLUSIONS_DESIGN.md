# 全局文件树排除规则

状态：已实现。对应 [issue #39](https://github.com/ywleeo/mark2/issues/39)。

## 目标与边界

用户可以隐藏文件树中的指定文件、目录和路径，减少工作目录中的干扰。
规则只控制工作区发现和展示，不删除磁盘文件，不改变文档身份、保存逻辑或文件访问权限。
手动打开的文件及已有标签页继续可用，根文件夹始终保留。

首版采用应用级规则，对所有已打开的根文件夹生效；各根目录分别计算相对路径。
暂不增加项目配置文件、规则继承、否定规则或自动读取 `.gitignore`。
Git 忽略规则用于版本管理，不能直接推导用户希望隐藏哪些文稿。

## 设置与交互

设置中的“文件”页由 `SettingsFileExclusionsSection` 管理：

- 排除规则列表：编辑、添加、移除、逐项启用或关闭。
- 总开关：“启用文件树排除”。
- 独立开关：“全文搜索同时排除”，默认开启；关闭后仅影响文件树展示。
- 恢复推荐规则，并解释规则示例和命中范围。
- 规则格式错误时，在对应行提示；保留上次有效配置，不部分应用。

沿用现有设置的提交与取消行为。提交成功后立即刷新目录，保留仍可见目录的展开状态、
标签页、选中文档和滚动位置；被隐藏条目的展开记录可以保留，关闭规则后可恢复。

默认规则包含当前已经隐藏的系统杂项，以及 `.git` 和 `.gitignore`，均可由用户关闭：

```text
.DS_Store
Thumbs.db
desktop.ini
.localized
.git
.gitignore
```

不默认隐藏所有点号文件，以免隐藏 `.env`、`.github` 等用户需要阅读的内容。
`.git` 同时匹配同名文件和目录，覆盖 Git worktree 使用 `.git` 文件的情况。

## 匹配语义

使用成熟 glob 匹配库，限制为清晰、可测试的语法子集，不手写正则转换器。

| 示例 | 含义 |
| --- | --- |
| `.gitignore` | 任意层级的同名文件或目录 |
| `node_modules/` | 任意层级的同名目录及其内容，不匹配同名文件 |
| `*.log` | 任意层级名称匹配的条目 |
| `/drafts/` | 当前根目录下的 drafts 目录及其内容 |
| `notes/private/` | 相对于当前根目录的指定目录及其内容 |
| `**/cache/` | 任意深度的 cache 目录及其内容 |

支持 `*`、`?` 和作为完整路径段的 `**`；`?` 匹配单个 Unicode 字符。
不支持否定规则、方括号、花括号扩展和正则表达式。
内部统一使用 `/` 分隔符。规则先去除首尾空白，拒绝盘符路径、UNC 路径及 `..` 路径段；
单个前导 `/` 始终表示相对于工作区根目录的锚定规则。
匹配区分大小写，使同一条规则在 macOS 和 Windows 上具有一致语义。
目录被排除后，其后代也被排除；直接定位后代路径不能绕过祖先目录规则。
多根目录重叠时，每棵根目录树独立计算匹配上下文。

## 模块职责

持久化使用独立的 `createStore('file-exclusions', { version: 1 })` 命名空间，
规则独立于 `editorSettings` 和 `AppState`。配置形状：

```json
{
  "enabled": true,
  "applyToSearch": true,
  "rules": [
    { "pattern": ".git", "enabled": true },
    { "pattern": ".gitignore", "enabled": true }
  ]
}
```

1. `modules/file-exclusions/`：规范化配置、持久化、发布有效规则变更；设置组件只处理展示和输入。
2. `src-tauri/src/file_exclusions.rs`：使用 `glob` 编译并校验规则，统一处理名称、路径和目录祖先匹配。
3. `src-tauri/src/workspace_files.rs` / `src/api/fileExclusions.js`：复用既有目录读取能力，接收根路径和规则快照，返回过滤后的条目。
   通用 `fileService.list()` / `read_dir` 保持完整目录语义，其他功能不会意外丢失文件。
4. `FolderLoader.readDirectory()`：调用工作区目录查询，在排序和渲染前拿到可见条目。
   加载、展开、刷新、watcher 更新、定位文件均复用此入口。
5. `workspace_search.rs`：每次搜索编译一次同样的规则；遍历前剪枝被排除目录，文件读取前过滤被排除文件。
   应用规则仅约束从目录中发现的文件；用户显式打开的单文件目标仍允许搜索。

搜索现有的依赖和构建目录跳过策略继续独立存在，设置中注明：关闭“全文搜索同时排除”
仅关闭用户规则，不代表全文搜索将扫描全部依赖、二进制文件和构建产物。

规则提交时广播版本变更：文件树刷新可见目录，搜索取消旧请求并按新快照重新执行。
异步目录查询同样核对规则版本，丢弃旧响应，防止已隐藏条目被迟到的结果重新插入。
目录 watcher 保留现有监听机制，首版不为显示排除重构底层文件监听。
应用其他窗口通过相同存储命名空间的 `storage` 事件同步配置，校验过期的同步结果不会覆盖更新的本地提交。
